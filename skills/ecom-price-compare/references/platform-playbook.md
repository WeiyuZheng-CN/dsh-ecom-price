# 平台手册：淘宝 / 京东 实测踩坑记录

全部结论来自一次真实采购（46 项清单、约 40 次成功抓取），不是推测。

## 一、CDP 与浏览器

**不能接管已经开着的浏览器。** CDP 是启动期开关，运行中的进程加不上。判断方法：

```powershell
Get-CimInstance Win32_Process -Filter "Name='msedge.exe'" |
  Where-Object { $_.CommandLine -match 'remote-debugging-port' } | Measure-Object   # 0 就是没开
```

**Chromium 136+ 拒绝「默认 user-data-dir + 调试端口」组合**，报错大意是 “DevTools remote debugging requires a non-default data directory”。所以必须用独立目录；独立目录拿不到原 profile 的登录态，代价是**要重新扫码一次**。

**Edge 首启会抢页面。** 新 profile 第一次启动会弹「同步浏览数据」全屏页，把目标页顶掉，表现为 `document.title` 变成一段同步文案。`launch-edge-cdp.ps1` 里加了 `--disable-sync` 和抑制 FRE 的 feature 开关解决。

**权限弹窗会插进 target 列表。** 淘宝会弹「访问此设备上的其他应用和服务」，它是 `edge://permission-request-dialog/` 类型、排在 `page` 列表第一位，会让「取第一个 page」的逻辑导航错对象。`cdp.mjs` 里 `pickTarget` 已过滤非 http(s) 页面。

## 二、登录态（最重要的一条）

**换网络 = 掉登录态。** 两次换网后都出现了同一现象：

| 检查 | 换网前 | 换网后 |
|---|---|---|
| `total` cookies | 43 | 39 |
| `unb`（淘宝用户 ID） | 有 | 无 |
| `pin` / `thor`（京东） | 有 | 无 |
| 页面抬头 | 昵称 | 亲，请登录 |

症状会伪装成"反爬"：淘宝从商品详情页开始跳登录页，京东直接返回只有导航栏的空壳（约 1.1 KB 文本、0 张卡片）。**先查 cookie 再怀疑限速**，顺序反了会白白降低抓取频率、白白分批。

恢复方式：开可见窗口 → 导航 `https://login.taobao.com/member/login.jhtml` → 用户扫码。扫码成功的判据不是截图，而是：

```powershell
node scripts/cdp.mjs cookies 'https://www.taobao.com' | Select-String taobaoLoggedIn
```

实测：登录态恢复后，**20 项连续抓取零拦截**；而掉登录态时，第 1 项就可能失败。所以"分批"不是主要手段，"保持登录"才是。

## 三、淘宝

**列表页价格被脱敏。** DOM 里是字面的问号字符（码位 `0x3f`），不是 PUA 字形、不是懒加载：

```
["4??", "44", "8?", "6?", "5?", "7?"]   ← priceInt 元素的 innerText
```

排查过并排除的：滚动、等待几分钟、翻页都不变；`navigator.webdriver === false`、UA 无 Headless；内嵌 JSON 无价格；`fetch`/`XHR` 钩子抓不到 mtop 响应（SPA 初始化时已持有原始引用）。**截图里显示的也是 `??`，OCR 也救不了**。

→ 所以：列表只用来**发现候选**（标题、店铺、销量、链接可信），价格必须进详情页取。

**详情页取价的选择器陷阱。** 价格数字所在的外层 `div` **没有 class**，`[class*=price]` 什么都选不到。可靠锚点是 `￥` 符号元素：

```js
const unit = document.querySelector('[class*="unit--"]');
const box = unit?.parentElement?.innerText;   // "￥39.9"
```

店铺名锚点：`a[href]` 里形如 `https://shop<数字>.taobao.com/...` 的那个链接，文本形如「米粉品牌壹号店 4.3 88VIP好评率96%」，要把尾部评分切掉。

**列表卡片抽取**：锚点走 `a[href]` 中匹配 `item.taobao.com|detail.tmall.com` 的链接，向上爬最多 6 层找到含价格文本的容器。每张卡要同时保留 `text`（全文 220 字），因为 `a.title` 常常只有品牌名（例如"蒙玛特"整条），单靠它做关键词匹配会误判。

## 四、京东

**搜索卡片没有 `<a href>`。** 2024 版搜索页是纯 JS 点击卡片，类和哈希化（`_card_1y1ag_92`），`li.gl-item` 全部消失，卡片里查不到 `item.jd.com`。

**sku 藏在客服链接里**：

```
//chat.jd.com/index.action?entry=jd_search&pid=<sku>&seller=<店铺>&wname=<标题>&commentNum=<评价数>
```

→ 商品直链 = `https://item.jd.com/<pid>.html`。这一招目前是京东列表页取 sku 的唯一可靠路径。

**参数是双重编码的。** `searchParams.get()` 解一次后仍是 `%E6%83%A0...`，要循环 `decodeURIComponent` 直到不含 `%XX`。

**价格直接可读**，不用进详情页：卡片全文里第一个 `¥` 后的数字是券后价，第二个常是划线价。注意数字被空格拆开（`"¥ 33 . 91"`），要先去掉空白再转数字。

**约 12 次连续搜索后返回空壳**：标题正常、导航栏正常，但卡片数归零。重载无效；登录态本身没掉（`pin`/`thor` 还在）。此时换淘宝或等冷却。

**关键词没结果时会退化成热门词页**（"荣耀magic6手机壳 啫喱水 ..."），卡片数 0。可在脚本里做一次"收紧关键词"重试。

## 五、选品与限速

**关键词命中 ≠ 买对货。** 实测误判：

| 想买 | 抓到 | 问题 |
|---|---|---|
| 石绿颜料 500ml | 青竹 **金色**丙烯 | 匹配到品牌+品类，颜色不符 |
| 朱红 250ml | 贝碧欧 **调和液** | 匹配到"贝碧欧+丙烯+250ml" |
| 象牙黑 1L | 温莎牛顿 **300ml** | 规格不符 |
| 软尺 2m | 得力 **钢卷尺** | 品类不符，弧形墙无法使用 |

对策：给每项一个 `must` 必含词（颜色/品类），匹配卡片**全文**而非标题；仍然要人工看一遍链接。

**价格单位陷阱**（会让总价差几倍）：

- 笔刷、勾线笔、铅笔：页面多为**单支价**，清单要的是支数/套装
- 路锥、警示牌：**单个价**，清单要 4 个
- 颜料：`1L` 与 `1kg` 不等价（颜料密度约 1.3，1kg ≈ 0.77L），按升比较才对
- 罩面漆：按桶还是按 kg，直接影响 2 倍差异

**分批参数**（登录态正常时）：`--batch 8 --batchpause 60 --pause 3000`。实测 8 项 + 12 项两批连续零拦截；掉登录态时任何参数都救不了。

## 六、Node 侧踩过的坑

| 现象 | 原因 | 修法 |
|---|---|---|
| 每次调用空转 30 秒才退出 | `send()` 里 `setTimeout` 定时器没清，闭包留住事件循环 | 定时器 `unref()` + 解析后 `clearTimeout` |
| 退出时报 `Assertion failed: !(handle->flags & UV_HANDLE_CLOSING)` | 在 socket 关闭过程中 `process.exit()` | 等 `close` 事件或 400ms 超时后再退出；错误路径只设 `process.exitCode` |
| 注入的 JS 报 `SyntaxError: Unexpected token '.'` | 外层模板字符串把正则里的 `\/` 吃掉，页面侧变成 `//` 注释 | 注入代码里的反斜杠要写双份，或用 `indexOf/startsWith` 代替正则字面量 |
| 选择器报 `not a valid selector` | `a[href*=item.jd.com]` 未加引号 | 属性值含点号必须写成 `a[href*="item.jd.com"]` |

## 七、输出约定

- 抓取结果按 id 增量落盘，随时可续跑；合并时**有价的记录不能被无价的覆盖**（京东会为失败项写空记录，容易把淘宝的好数据顶掉）
- 报表里链接列必须是真超链接（openpyxl `cell.hyperlink`），"商品页"与"按推荐款搜"两种语义要区分：前者价格已核，后者只是预填搜索
- 原清单的字体/底色标注要保留语义：黄底=可精简、红底=备预案、红字=看情况、theme3 色=型号有问题；注意 `FFF7F5F1`、`theme7/0.4` 是隔行底色，不是标记

## 八、SKU 级核价：一次把「规格 → 价格」摊开（2026-10 实测，最重要的一节）

前面所有取价手段（列表卡片、详情页首屏价格盒）拿到的都只是**最低 SKU 的价**。清单要的是「某个规格」的价，两者可以差 10 倍。翻车样本：一条「缓干剂 250ml」记成 3.8 元，而 3.8 是同链接里**60ml 调和液**的价。

**淘宝/天猫商品页自带完整 SKU 表**，不用点选就能读：

```js
const res = window.__ICE_APP_CONTEXT__.loaderData.home.data.res;
res.skuBase.props[].name / .values[].{vid,name}   // 属性组与值（颜色、颜色数/规格…）
res.skuBase.skus[].{skuId, propPath}              // propPath = "pid:vid;pid:vid"
res.skuCore.sku2info[skuId].price.priceText       // 该 SKU 的价
res.skuCore.sku2info[skuId].quantityText          // 有货/无货
```

结构要点：

- 路由名是 `home`（不是 `item`/`detail`）：`loaderData.home.data.res`
- `sku2info` 里还会有一条 `skuId: "0"`，它代表「起价」，**别拿它当某个规格的价**
- 数据是 SSR 注入的，但 hydration 后才齐；实测要 poll 到 15 秒（脚本里已实现）

`scripts/audit.mjs` 就是把这张表批量导出来的：`node scripts/audit.mjs urls.json aud.json`。拿到 `skus[]` 后按 `attrsText` 找清单规格，而不是取 `minReal`。

再让 `scripts/ladder.py --aud aud.json --xlsx 清单.xlsx` 把两者并排打印：每个规格一档价、多色套装单列、并标出表内「数量×单价≠小计」。实测它能自动重现本次全部结论（塑料碗 20个=4.9 而 50个=7.9；扇形笔 2号=2.6 而 4号=3.8；勾线笔 000#=4 而 0#=4.5）——这类「清单价 = 邻档价」的错，肉眼扫阶梯表最快。

**判错口诀**：把该链接的价格阶梯列出来（如 100ml=4.XX / 300ml=1X / 500ml=2X / 1000ml=3X），清单单价落在**哪一档**，就说明它其实是哪个规格的价。

## 九、打码价（fuzzyPrice）：位数就是量级

部分店铺把价格数字替换成 `?`，**与是否登录无关**（`sku2info` 里就是打码的）：

```
"price": { "fuzzyPrice": true, "priceText": "4.??", "priceDesc": "起" }
```

- `4.??` → 4.0–4.99；`2?` → 20–29；`1??` → 100–199
- 只能判断「清单价是否同量级」，给不出精确数
- 对策：换不打码的店 / 按量级下限计入并写区间 / 标「下单前确认」
- ⚠️ 别把 `4.??` 写成 `4.08`：伪精度会让人以为核过了

## 十、登录态会中途掉（两次复现，处置顺序固定）

| 触发 | 现象 | 判据 |
|---|---|---|
| 长跑抓取（~20 次导航）后 | 详情页整页跳 `login.taobao.com/havanaone/login/login.htm?bizName=taobao&redirectURL=…` | `cookies` 里 `unb` 消失、`total` 从 42 掉到 36 |
| 访问 H5 详情页 | `main.m.taobao.com/detail/index.html?id=…` 跳到 `h5api…/login_jump`，**顺带把 PC 登录态一起清掉** | 同上 |

结论：

1. **抓价流程里不要碰 H5 页**（`main.m.taobao.com`、`h5api.m.tmall.com`），它既拿不到数据又会带走登录态
2. 长任务中途查一次 cookie；掉了就停下来让用户扫码，别当成"反爬限流"降频硬跑
3. 页面标题出现 `登录` + 正文「手机扫码登录」= 登录态问题，不是验证码

## 十一、验证码与 403：识别 + 绕开入口，不硬闯

| 现象 | 识别 | 处置 |
|---|---|---|
| 天猫验证码 | `document.title === "验证码拦截"`，正文「将满足描述的所有图片拖放到指定区域后提交」 | 不要尝试自动化。等几分钟，或换 `item.taobao.com/item.htm?id=<同一 id>` 入口重开（实测能过） |
| 京东 PC 频控 | 落到 `pc-frequent-pro.pf.jd.com/?from=pc_item&reason=403`，标题「PC频控页 -京东商城」 | 详情页冷却后再试；这段时间用搜索卡片名核规格（见下） |
| 淘宝搜索登录墙 | 列表 `count=0`，正文首部「亲，请登录」 | 登录态掉了，见第十节 |

**天猫商品可以用 `item.taobao.com/item.htm?id=<id>` 打开**：会 302 回 `detail.tmall.com`，但入口不同，实测比直接开 tmall 链接更少触发验证码。

**京东被判频控时，规格信息仍可从搜索结果卡片名读**：卡片标题本身常带规格，例如
`久诺…封闭抗碱底漆 1KG【约刷4-5平方米/两遍】`、`海斯迪克…细号(240目-320目)10片装`、`包大师美纹纸胶带24mm*20m*6卷/筒`。
够用来回答「这个价对应哪个规格」——本次 6 个京东项就是这样核的。

**价格数字会被 span 拆开**：`￥4 . 08`。正则前先去空白：`box.replace(/\s+/g,'')`，否则只抓到 `4.`。

## 十二、真实错例库（拿来做对照，判错时先比对）

一次 38 行墙绘清单的核对结果：31 个必需项里 **12 项单价对应的是更小规格**，另有 4 项数量/整包口径错。

| 清单写法 | 表里的价 | 实际对应 | 该怎么算 |
|---|---|---|---|
| 缓干剂 250ml | 3.80 | 「新型调和液 **60ml**」 | 该店无 250ml 缓干剂：调和液 250ml 10.3；缓干剂本体 125ml 13.8 |
| 羊毛板刷 3寸 | 15/把 | 「**1/2寸** 宽15mm」 | 3寸【宽76mm】= 50/把 |
| 9寸滚筒+托盘 | 18 | 「**3寸羊毛刷** 1 把」 | 滚筒带支架 33 + 托盘 20 = 53 |
| 4寸小滚筒 | 5 | 「**2寸手柄**一只」（只有手柄） | 4寸滚筒一套 13.8/个，且规格写 2 个 → 数量 2 |
| 调色盘 大号 | 4 | 「**十孔**调色盘 H016」 | H015 大号 = 9/个 |
| 一次性碗 500ml 50个 | 4.90 | 「**普通薄款 20 个**」 | 加厚 500 型 50 个 = 7.9 |
| 马利丙烯 500ml | 17.70 | 不属于任何档（打码店：100ml=4.XX、300ml=1X、**500ml=2X**、1000ml=3X） | ≥20/罐 |
| 尼龙笔套装 10~12支 | 45 | 链接只有单支和「5支全套 90」 | 90（或换链接） |
| 扇形笔 2号 | 3.80 | **4号**的价 | 2号 = 2.6（这条方向相反：偏高） |
| 勾线笔 0/2号 | 4.00 | **000#**的价 | 0号 4.5、2号 5.0 |
| 美纹纸 4卷 | 8.7（数量填 5） | 「24mm*20m***6卷/筒**」整筒价 | 数量填 1；48mm 另拍 |
| 水桶 10L「2个」 | 24（数量填 1） | 单桶价 | 数量填 2 |

**表内自查三连**（不联网就能抓出大半）：

1. `数量 × 单价 ≠ 小计` → 口径已经乱了（美纹纸就是：数量 5、单价 8.7、小计 8.7）
2. 规格里写了件数（2个/4卷/各2支），数量列却是 1
3. 单价低于同链接价格阶梯的最低档 → 一定是从别处串来的
